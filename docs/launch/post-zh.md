## 一、长文版（V2EX「分享创造」/ 即刻 / 掘金）

**标题备选**

1. 我做了一个本地小工具，让 AI 编程 Agent 不再推翻已经说好的事（开源）
2. 说了「先讨论，不要改代码」，AI 还是改了？我给 Agent 装了一道本地规则边界

**正文**

我业余时间用 Claude Code、Codex、OpenCode 这些 AI 编程工具做一个不小的项目。最让我头疼的往往不是 AI 写不出代码，而是它会重新决定已经定好的事：

- 我说「先讨论，不要改代码」，它下一步就开始改文件；
- 上周约定好的规则，换个会话、换个模型，就被重新解读；
- 它说「完成了」，其实该跑的检查一个都没跑；
- 遇到 git 钩子拦路，它会顺手加个 `--no-verify`。

把要求写进 CLAUDE.md、AGENTS.md 有用，但那只是建议，模型可以不听。所以我做了 **SOP Control**：一个放在项目仓库里的本地控制面。

**它做什么**

- **规则跟着仓库走**：规则写在项目的 `.sopcontrol/` 里，每条都记着来自哪句原话、谁确认的、适用什么范围、现在第几版。模型提议的东西，没有人确认就永远只是建议。
- **工具调用前先过一道检查**：Agent 每次调用工具，都先经过本地判定（Claude Code 的 PreToolUse 钩子、OpenCode 插件，或命令包装）。这条路径是确定性的代码，**不调用任何大模型，也不联网**。
- **推送前有门**：`git push` 前自动跑检查，判定失败或证据账本被改动就不让推。
- **「说完成」和「验证过」分开记**：任务要经过验证才算完成，模型自报不算。

**60 秒看效果**（不需要模型、不需要 API key，只在临时目录里跑）：

```bash
git clone https://github.com/mixxmax/sopcontrol.git && cd sopcontrol
python3 -m venv .venv && source .venv/bin/activate && pip install -e .
scripts/demo.sh
```

脚本把 Claude Code 调用工具时发给钩子的真实请求逐个交给 `sopctl`，你会看到：正常改代码放行；你说了「先讨论」之后，它用写文件工具或 Bash 改文件都被拒，只读命令照常可用，它想自己解锁也被拒；你说「可以改了」之后放行；`--no-verify`、删掉推送前钩子、用 `core.hooksPath` 换个写法跳过检查、直接改规则文件、改 `.claude/settings.json` 卸钩子，都被拒。

**一个真实教训**

我自己的项目 JobsFlow（一个香港求职全流程系统）就跑在它上面：扫描、入表、生成材料、投递前检查，每个写操作都要先过准入，还要一次性的能力票据。

最有用的一次教训，恰恰关于控制层本身：我的测试默认把强制模式关掉了，结果有个票据相关的 bug，让一条命令在真实的强制模式下根本走不通，而全部测试一直是绿的。**测试里关着的控制层，等于没测过。** 后来我把测试改成开着强制模式跑，才把它抓出来。

**发布前我自己先攻了一遍**

我按最容易想到的方式试着绕过它，找到的都修了：讨论锁生效时 Bash 只放行只读命令；Agent 不能自己解锁；删推送前钩子、改 `core.hooksPath`、`git -C . push` 这些换个写法的推送，也都绕不过检查了。

**目前还做不到的（Beta）**

- 在 Claude Code 里，讨论锁还不会从你的消息里自动识别，需要你执行一条命令来设置；
- 写到任务范围之外的文件，是在提交任务时被拒绝，而不是写入的那一刻。

它约束的是「合作的 Agent」，不是沙箱，也不防恶意程序。

**想听听你的意见**

1. 你最希望给自己的 Agent 强制执行哪些规则？
2. 「规则空间 / 解法空间」这套说法，你觉得清楚吗，还是只是多了一堆新词？

## 二、小红书短版

**标题**：AI 写代码总把说好的事推翻？我做了个开源小工具

**正文**

用 Claude Code / Cursor 写代码的你，是不是也遇到过：
😤 说了「先讨论别改代码」，它转头就改了
😤 上周定好的规则，换个会话就不认了
😤 它说「做完了」，检查其实一个没跑

我做了个开源工具 **SOP Control** 👇
✅ 规则存在项目里，换会话、换模型都不丢
✅ AI 每次动手前先过一道本地检查（不调用大模型，不联网）
✅ 你说「只讨论」，它就改不了文件（换成 Bash 也不行），直到你说「可以改了」
✅ 想用 --no-verify 或删钩子绕过检查？拦下

60 秒本地演示，不需要 API key：
GitHub 搜 mixxmax/sopcontrol，跑 scripts/demo.sh
